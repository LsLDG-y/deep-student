# 学习资料交互 × 笔记手感：UX 改进方案

日期：2026-09-30。范围：①在聊天里使用 PDF/教材/附件/知识库等学习资料；②笔记编辑器对齐 Notion 的手感、视觉与结构。

依据：本轮为代码通读（Chat V2、PDF 阅读器、Learning Hub 引用链路、Crepe 笔记全链路），视觉判断参考 `docs/research/assets/notes-ux-*-20260912/` 的真实应用截图。**本轮未在运行中的应用上逐项复测**，标注"待复测"的条目须在 `npm run tauri dev` 中确认后再动手。9/12 那轮审计已解决移动端布局、命令收口与保存可靠性，本文不重复，只处理"顺不顺手、好不好看"。

## 一、核心判断

1. **资料交互的根问题是"没有一个归属地"**。同一份资料有 5 种打开方式（聊天右栏、整页 Learning Hub、学习桌面独立窗口、图片模态、文本模态），3 套送入聊天的通路（`referenceToChat` / `injectToChat` / `selectionToChat`，外加 PREFILL 与页码引用事件）。用户点一个引用，结果取决于资料类型和外壳模式，最常见的结果是**被带离聊天**。
2. **引用只做到"页"，没做到"那句话"**。选区引用已经存了原文和页码，但回跳时只闪一下整页，从不高亮被引用的句子——"每条引用都回得到原文"在产品里其实只兑现了一半。
3. **笔记不像 Notion，主要不在功能，而在 chrome 和密度**。slash、块手柄、拖拽、toggle、callout、双链、反链都已经有了；拉开差距的是：常驻的 Word 式格式工具条、标题与正文之间的元数据行、过松的块间距、标题和正文不对齐、标题→正文不连贯、没有子页面。前四项都是低成本高收益。

### 目标形态：资料留在聊天旁边

一条原则：**在聊天里打开的任何资料，都在聊天右侧的资料栏打开；去 Learning Hub 是显式选项，不是默认结果。**

- **资料栏**：可拖拽宽度（复用画布模式已有的 PanelGroup）；顶部是标签页，一个标签对应一份资料；标签状态**按会话保存**，切回会话时还原；栏头加「本会话资料」下拉，列出这个会话引用过的所有资料，关掉的可以重新打开。
- **精确回跳**：`pdf-ref:focus` 携带原文片段；阅读器复用现有搜索 mark 能力，滚动到并高亮那句话，持续约 2s 后淡出为浅色底纹。用户点击统一走 `requestPdfPageFocus`（ack + 挂起重试），不再盲发。
- **徽章**：显示「《书名》p.47」（窄处显示书名缩写），悬停出页面缩略图和原文片段；文档身份从引用元数据解析，不再扫消息猜。
- **选区工具条合一**：一条工具条，颜色作为第一组；聊天相关只保留一个「引用到聊天」（选区快照），「整本加入对话」挪进更多菜单；「出题」回到工具条。
- **送入聊天的统一契约**：一个 `sendToChat(ref, { switchToChat, insertMode })`，从任意阅读器发出都：①没有会话就建草稿会话 ②toast 带「前往对话」 ③文本在光标处插入，不覆盖草稿。
- **输入框找资料**：`@` 同时补全资源（书、笔记、导图、文件），支持从侧栏/Finder 拖入输入框。

### 分步

1. **P0（1–2 天量级）**：引用默认在右栏打开（#1）；用户点击走 ack 跳转（#5）；草稿不被覆盖、toast 带「前往对话」（#8）；删掉死按钮与调试 `console.warn`。
2. **P0**：引用句高亮（#2）——体验收益最大，也是宣传片"每条引用都回得到原文"的兑现。
3. **P1**：资料栏可拖宽 + 标签页 + 按会话保存 + 本会话资料（#4、#10）；徽章书名与悬停预览（#6）。
4. **P1**：选区工具条合一、去掉「添加到聊天」歧义（#3、#12）。
5. **P2**：`@` 资源补全与拖入（#9）；学习桌面事件归属守卫（#11，先复测）；扫描版 PDF 的 OCR 文本层。

### 目标形态：页面就是文档

- **安静的页面**：去掉常驻格式工具条。行内格式只在选中文字时出现（合并为一条浮动条，带颜色和「问 AI / 加入聊天」）；块操作只在块手柄菜单；页面级操作（导出、历史、宽度、制卡）进右上角「•••」。顶部只留面包屑、保存状态（安静的文字，2 秒后淡出）和「•••」。
- **标题区**：悬停标题时在其上方淡入「添加图标 · 添加封面 · 添加属性」；标签和字数移进属性区，默认收起。
- **排版重定一套 token**：正文 16px / 行高 1.5，块间距 2px + 块内上下 3px padding；H1/H2/H3 上方额外留白（约 1.4em / 1.1em / 0.9em）；标题 40px/700；内容列 708px（宽版 ~1000px）；标题、属性、正文同一左边线；手柄落在左侧 gutter 里不占内容宽度。浅色/深色各给一份对照截图做验收基准。
- **键盘连贯**：Enter/↓ 从标题进正文；正文首块 ↑/Backspace 回标题；新建笔记光标在标题；Esc 选中当前块，↑↓ 扩选，再按 Delete/⌘D/拖拽成批操作。
- **子页面**：笔记可以作为父级；`/页面` 在当前笔记内新建子页并插入页面链接块；侧栏树里笔记节点可展开。这是数据模型变更（树节点类型 + 移动/删除/回收站的级联语义），需要单独评审。
- **@ 统一**：`@` 提及笔记、教材页、导图、日期；`[[` 保留为同一能力的别名，弹出同一个选择器，避免两套机制。

### 分步

1. **P0（视觉手感，2–3 天量级，不动数据）**：去掉常驻工具条、合并浮动条；标题区和元数据行重排；排版 token 重定、修左边线对齐；标题↔正文键盘连贯；新建即聚焦标题。做完拿同一篇笔记和 Notion 并排截图验收。
2. **P1**：页面图标/封面（悬停入口、emoji 选择器、封面图片）；文字色/背景色；`> ` 改为 toggle、toggle 标题；Esc 块选择与多块批量操作；侧栏以页面树为主体。
3. **P1**：选区「问 AI」和空行唤起 AI（复用已有的 canvas_note 技能与 AI diff 审阅，不新造写入通路）。
4. **P2**：子页面（数据模型评审后再做）；`@` 统一；嵌入块（网页书签、视频）；`CrepeEditor.css` 去 `!important` 重构，与 P0 的 token 一起落地以免回归。

编辑器底座继续用 Crepe：上面所有改动都落在宿主 chrome、CSS token 和少量 ProseMirror 插件上，换底座解决不了，反而会重写 Markdown、附件、导图、AI 产物和 DSTU 保存协议（与 9/12 结论一致）。

## 四、需要产品决定的事

1. **Learning Hub 的角色**：引用默认留在聊天右栏后，整页 Learning Hub 只作为"资料管理"入口，不再是阅读的默认落点。
2. **「添加到聊天」（整本）是否保留为一级操作**：建议降级到更多菜单，一级只留选区引用。
3. **笔记是否支持嵌套页面**：会改变树的数据语义，影响同步、回收站和导出。
4. **常驻格式工具条是否全部去掉**：建议桌面端去掉；部分用户依赖按钮式格式，可在设置里保留"显示格式工具条"开关。

## 五、验收方式

每一项完成后在 `npm run tauri dev` 的真实应用中验证（不用 demo 页面），并留截图：经典外壳、学习桌面各一遍；浅色/深色各一遍；笔记排版与 Notion 同内容并排对照。资料交互的验收用例：多 PDF 会话里点不同书的徽章、冷启动后第一次点引用、发送选区时输入框已有草稿、切会话再切回来右栏还原。
