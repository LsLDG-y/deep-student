# 学习闭环与知识库审计（2026-10-01）

> 方法：五路并行只读调研（资料↔对话、知识库、笔记、练习复习、子应用互通），全部基于代码与本机运行态
> （dev 日志 + 只读 SQLite 查询），未改动任何数据。关键论断已二次抽查。
> 「疑似」= 静态分析结论，需运行时确认。状态记号：✓ 双向通 · → 单向 · ✗ 断裂 · — 缺失。

## 一、结论

1. **知识库在本机实际不可用，且学习者完全不知道。** 93 个资源，向量 0 条（Lance 目录 0 B）。40 项失败
   全部是嵌入模型配置错误；3 项「已索引」是 OCR 为空的截图（假成功）。界面只显示「40 项索引失败」。
2. **主干是「聊天 + Agent」单中心辐射**：Agent 工具几乎能读写每个子应用，资料→聊天、聊天→产物都能走通。
   但**几乎所有产物都不记录来源**，学习者「去得了、回不来」：
   笔记不知道来自哪次对话，卡片和题目不知道来自哪一页，资料不知道被哪些对话、笔记引用过。
3. **练习复习是四条互不相通的线**：FSRS 卡片队列、SM-2 错题复习计划、笔记 `study_review_date`、
   外部 Anki。各自对「掌握」有一套口径；掌握度数据只给 AI 看，学习者看不到；「今日复习数」在不同入口不一致。
4. **真正双向打通的只有一段**：PDF 划词引用到对话 ⇄ 引用徽章跳回原页。
5. **工作台模式是最大的系统性断点**：经典壳能用的若干跳转（题目集引用、知识库定位、导图嵌入的「打开」、
   快捷助手打开资源），在工作台下没有对应处理（疑似全部失效）。

### 闭环 6：知识库（上传 → 解析 → 索引 → 召回 → 引用 → 更新）

**本机实测（slotA，`vfs.db`）：**

| 状态 | 数量 | 原因 |
|---|---|---|
| failed | 40 | 23 项「默认文本嵌入配置已禁用或能力协议不匹配」；17 项「找不到嵌入模型配置」（含一份已有文本的 PDF） |
| pending | 34 | 没有任何索引单元 |
| disabled | 16 | 系统笔记、学习者画像、已删除项 |
| indexed | 3 | 全是空 OCR 的截图，0 个分块（假成功） |
| 向量 | **0** | `vfs_index_segments` 0 行，lance/kb 0 B |

**根因（已核实）：**
- 默认嵌入配置指向内置的 `builtin-sf-embed`，但这份配置只有编译时注入 `SILICONFLOW_BUILTIN_EMBED_KEY` 才存在（`vendors/siliconflow.rs:59`），在开发版里是悬空引用。
- 自动回退要求「恰好只有 1 个」已启用的嵌入配置（`rag_extension.rs:229`），多于一个就拒绝选择。
- 已失败的条目在配置修好后**不会自动恢复**。

| 阶段 | 评分 | 要点 |
|---|---|---|
| 格式覆盖 | 可用 | docx/pdf/md/html/xlsx/pptx/epub/rtf/csv 等，200MB 上限，有 zip 炸弹防护 |
| 网页导入 | 部分 | 只能通过聊天工具；资源库没有 URL 导入 |
| 扫描件 OCR | 部分 | 依赖 VLM 引擎；没有引擎时静默留空，不提示 |
| 图片 | 部分 | 空 OCR 被标为「已索引」 |
| 表格 / 公式 / 图 | 部分 | 抽取器只给题目导入用，知识库没用上 |
| 切块 | 部分 | 固定 512 字符、不感知标题；最小块长按字节计，中文偏差 |
| 页码定位 | 部分 | 原生文字 PDF 的页码是**均匀摊段落估算**的（`indexing.rs:1375`），引用页码可能不对 |
| 嵌入未配置 | **断裂** | 静默跳过，任何地方都没有提示；`rag_no_embedding` 文案存在但从未使用 |
| 本地 / 离线嵌入 | 缺失 | 没有 fastembed / ort / candle |
| 换模型 / 换维度 | 断裂 | 报原始英文的 stale profile 错误，没有重建索引的引导 |
| 混合检索 | 部分 | 有 RRF，但「全文」路实为 SQL LIKE（≤12 个词），不是 BM25；`fts_weight` / `vector_weight` 是死配置 |
| 重排 | 部分 | 没配重排模型时静默跳过 |
| 查询改写 | 缺失 | — |
| 检索范围 | **断裂** | 会话选定的知识库范围 `rag_library_ids` 读出来后存进 `_rag_library_ids` 就丢弃了（`model2_pipeline.rs:5470`） |
| 注入对话 / 引用 | 部分 | 只有模型主动调工具才检索，预取路径是死代码；不校验引用编号是否存在（疑似） |
| 评测 | 缺失 | 没有召回金标集（只有 Anki 有） |
| 新鲜度 | 基本可用 | 编辑、移动、回收、恢复都会触发重建；没有 SQLite 与 Lance 的一致性校验 |
| 可观测性 | 部分 | 只显示原始错误文本，没有「去修复」入口 |
| 记忆 vs 知识库 | 部分 | 关闭记忆后，记忆笔记会混进知识库结果 |

## 四、修复路线（按学习者影响排序）

### P0：让核心能力「能用且可见」（每项 ≤2 天）

1. **知识库就绪性**：
   - 启动时修复悬空的 `builtin-*` 默认配置；有多个嵌入配置时自动选一个并告知；
   - 在 Finder 状态条、索引状态页、聊天知识库开关上显示「嵌入模型未配置」横幅，附一键前往配置；
   - 嵌入配置变更后，把因配置失败的条目重置为 pending、重试次数清零；配置类错误不消耗重试次数。
2. **检索范围生效**：在 `BuiltinRetrievalExecutor` 里强制应用 `rag_library_ids` 和选中的资源；关闭记忆时排除记忆文件夹。
3. **修掉已核实的坏按钮**：速答「存为错题」改走 `qbank_batch_create_questions`；命令面板备份 / 恢复接到数据治理流程，或先隐藏；PDF「添加到聊天」合并进「引用到聊天」。
4. **教材引用留在聊天页**：`tb_` 也走右侧面板，并改用带回执的 `requestPdfPageFocus`。
5. **工作台导航补洞**：`WorkbenchEventBridge` 接上 `navigateToExamSheet`、`DSTU_NAVIGATE_TO_KNOWLEDGE_BASE`、`NAVIGATE_TO_VIEW{openResource}`、`MOBILE_APP_NAVIGATE`。

### P1：溯源回链，让学习者「回得来」（每项约 1 周）

6. **统一的来源模型**：
   - 新增 `origin {sessionId, messageId, sourceRef: {resourceId, page | blockId}}`，写入笔记、卡片、题目、导图；
   - 笔记、卡片、题目详情显示「来自对话 / 来自第 N 页」并可点击跳转；
   - 修掉卡片库的 `chat_session` 死分支；生成卡片时保存 `documentId` 并建立关联。
7. **反查**：新增 `note_relations.list_by_resource` 和「讨论过此资料的对话」接口，在 PDF、题目、卡片侧显示「相关笔记 / 相关对话」。
8. **定位到具体文字**：
   - `pdf-ref:focus` 携带 quote，在文本层里闪烁高亮被引用的句子；
   - 笔记引用带标题或块锚点；导图引用定位到节点；
   - `[知识库-N]` 直接打开右侧面板并跳到对应页（定位信息增加 pageIndex）。
9. **错题进对话**：在题目视图加「问 AI 这道题」（注入题干、我的答案、解析、来源）和「生成同类题」。

### P2：把练习复习串成一个闭环（数周）

10. **统一「今日学习」**：新增 `learning_today_get_due` 命令，汇总 FSRS、SM-2、笔记复习日期和待办。首页、待办、仪表盘、提醒都改用它；长期把题目也纳入 FSRS。
11. **掌握度统一并对学习者可见**：
    - SM-2 复习和练习答对也回写掌握度；无 tag 的卡用卡组或文档兜底；
    - 提供掌握度总览和薄弱点视图；
    - 笔记的 `study_mastery` 显示系统掌握度作为参考。
12. **作文批改 → 错题本**；**番茄钟时长计入练习**；**确定性的周报**。
13. **阅读状态进上下文**：当前页、选区自动注入（可关），并支持 PDF 框选截图提问。

### P3：知识库质量工程（数周）

14. 内置本地嵌入模型作为默认回退（或在缺失时明确标注「仅关键词检索」）。
15. 全文检索改用 FTS5 或 Lance BM25（带中文分词）；查询改写或多查询。
16. 原生 PDF 按页提取文字（替代均匀估算），按标题切块，保存标题路径。
17. 召回金标集（50–100 题，Recall@5 / MRR）接入 CI，据此调 RRF 权重和阈值。
18. 换模型时引导重建索引；SQLite 与 Lance 一致性校验；资源库 URL 导入。
